# 全文索引热路径优化与验证

## 修改依据

在 20,000 条中英混合文本的公开 FTS 基准上观察到 IK 词典加载、停用词检查和词频聚合的重复工作。保留现有解析与检索语义，对热路径做如下调整：

- 同字符集的停用词查询直接使用原字符串，避免无实际转换的临时分配；不同字符集仍走原转换路径。
- 聚合词频时使用哈希表的原子插入或更新接口，减少一次查找；首次和重复词频沿用原逻辑。
- 已加载的词典使用读锁查找并持有引用；不存在时在写锁下二次检查并创建。
- 将词典的昂贵重建移出桶写锁，并用单独的构建锁串行化重建；发布状态仍持桶锁。
- 如果初始化时确认词典范围严格有序且不相交，以二分查找范围；否则回退原线性查找。

## 可复现正确性检查

启动 seekdb，并安装 MySQL 命令行客户端：

```bash
MYSQL_ARGS='-h127.0.0.1 -P2881 -uroot' python3 unittest/sql/fts/fts_regression.py
```

检查使用合成内容，覆盖 8 并发下 960 次 IK、BENG、space、ngram、ngram2 分词结果一致性，以及真实 IK 全文索引的创建、插入、更新、删除和 MATCH 结果。脚本创建带时间戳的新数据库，完成后保留以供检查；不会删除已有数据库。本机实测全部通过。另用相同测试语句比对基线和优化版的中英文、空值、特殊字符 TOKENIZE 及 MATCH 命中数、所测排序，结果一致。
